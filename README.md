Loan Risk AI System

An end-to-end AI/ML system for loan default risk estimation, combining a trained machine learning model with FastAPI model serving, LangGraph tool orchestration, RAG, MySQL persistence, Ollama, and Docker.

Overview

The system predicts a borrower's probability of loan default using a trained MLPClassifier.

Instead of exposing the ML model directly to the conversational layer, the model is served through a FastAPI service. A LangGraph agent can call this prediction service as a tool, retrieve relevant loan-policy information through RAG, and query historical predictions stored in MySQL.

The ML prediction represents a risk estimate and is not intended to act as an automatic loan approval or rejection system.

Machine Learning

The project evaluates several classification approaches for an imbalanced loan-default dataset.

Models explored include:

Logistic Regression
Decision Tree
Random Forest
Gradient Boosting
Gaussian Naive Bayes
Linear Discriminant Analysis
Quadratic Discriminant Analysis
Multi-Layer Perceptron

The final model is an MLPClassifier combined with StandardScaler inside a scikit-learn pipeline.

FastAPI Prediction Service

The trained pipeline is exposed through:

POST /predict

Example request:

{
  "Income": 65000,
  "LoanTerm": 36,
  "LoanAmount": 120000,
  "InterestRate": 14.5,
  "CreditScore": 610,
  "MonthsEmployed": 15,
  "DTIRatio": 0.42
}

Example response:

{
  "default_probability": 0.1515,
  "predicted_class": 0,
  "risk_level": "low"
}

The classification threshold is configurable separately from the model's probability output.

LangGraph Agent

LangGraph is used to orchestrate multiple tools.

The agent can:

Call the loan-default prediction API.
Retrieve relevant policy information.
Query historical prediction data.
Combine structured ML output with retrieved context.
Produce a natural-language explanation through Ollama.

The prediction logic remains inside the ML service rather than being generated by the LLM.

Retrieval-Augmented Generation

Loan-policy documents are split into chunks and embedded using Ollama embeddings.

Relevant chunks are stored and retrieved through Chroma.

Question
   ↓
Embedding
   ↓
Vector Similarity Search
   ↓
Relevant Policy Chunks
   ↓
Ollama
   ↓
Grounded Response

RAG is used for policy and contextual explanations, while the MLP model remains the source of the numerical default-risk prediction.

MySQL

Prediction events are persisted in MySQL.

Stored information includes:

Income
Loan term
Loan amount
Interest rate
Credit score
Months employed
DTI ratio
Default probability
Predicted class
Risk level
Timestamp

The agent can also use read-only SQL tools to inspect historical prediction information.

A dedicated database user is used instead of the MySQL root account.

Docker

The FastAPI prediction service can be packaged inside a Docker container.

Build the image:

docker build -t loan-risk-api .

Run it:

docker run -p 8000:8000 --env-file .env loan-risk-api

Swagger documentation is then available at:

http://127.0.0.1:8000/docs

When the MySQL server runs on the Windows host while FastAPI runs inside Docker, the database host is configured as:

host.docker.internal
Environment Variables

Sensitive database credentials are stored outside the source code.

Example .env.example:

DB_HOST=host.docker.internal
DB_PORT=3306
DB_USER=loan_app
DB_PASSWORD=your_password_here
DB_NAME=loan_ai

The real .env file is excluded from Git using .gitignore.
